# 架构

浏览器 React/Vite → Express HTTP/SSE → V2 领域服务 → SQLite。后台任务与平台适配器沿服务端统一写入机制工作。公开首版按单实例、单 SQLite 数据目录部署；不要让多个进程共享同一可写数据目录。

## 目录

- `src/v2/`：当前工作区、路由、管理和成员界面。
- `src/shared/`、`shared/`：共享展示及纯数据模型。
- `server/v2/`：身份、成员、档期、统计、平台管理、同步与通知。
- `server/storage/`：SQLite、迁移和底层存储。
- `server/api.js`：仍被 V2 装配调用的兼容业务入口；不是可直接删除的废弃文件。
- `scripts/`：安装、检查、迁移、备份及发布工具。
- `test/`、`test/support/`：测试与离线夹具，不属于生产运行依赖。
- `wechat-miniprogram/`：可选独立客户端。

## 关键约束

服务、repository、provider 和 routes 边界已经存在，新增功能应在所属领域实现。Discord、KOOK、微信账号及回调不得跨平台复用。所有权限依据服务端当前身份重新校验；客户端按钮可见性不能替代鉴权。

变更操作保留版本冲突、幂等键与撤权检查。后台采集由任务运行，读页面不应隐式发起外部采集。SQLite 写入必须沿已有事务与串行写机制；停止服务需排空任务并释放运行锁。

## 兼容与后续拆分

旧 API、JSON 数据迁移和部分 legacy UI 仍服务升级兼容。公开首版固定 V2+SQLite，新安装不从旧系统开始。对大入口的后续拆分应每次抽一个无状态组件或领域，保持原调用接口并运行对应领域测试；目录改名、格式调整与行为变化分开提交。
