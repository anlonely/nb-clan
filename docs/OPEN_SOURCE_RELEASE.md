## 贡献与后续维护

按目的拆分变更：分发与文档、安装和运行时、业务修复、测试与 CI。公开仓库首个提交对应完整、可验证的发行快照；后续功能通过独立 PR 进入。

`server/api.js` 仍承担较多兼容逻辑，后续可依次抽离平台消息格式、采集流程和管理接口。每次拆分应先固定输入/输出及停止语义，再进行小范围迁移，不与权限模型调整混合提交。

第三方服务的账号、真实 OAuth 回调、官方平台消息投递和公网 TLS 证书需要部署者配置并验收。自动测试中的回环替身与代理头验证不能替代这些真实环境检查。第三方依赖及媒体范围见 `THIRD_PARTY_NOTICES.md`。
